# Nithron AI lab: training

Training code for the models in the [lab roadmap](../docs/lab/ROADMAP.md). Not a dependency of nai-core:
the nAI image stays PyTorch-free.

Before using any model or dataset here, check that it is in the
[license register](../docs/lab/MODEL_AND_DATA_LICENSES.md) (principle 2). Training data comes only from
synthetic or permissively licensed sources, generated by approved open-weight teachers (principle 3),
and never from `evals/nai-bench/` (the scripts refuse it).

## Stage 1: embeddings (`embed/`)

Plan: [docs/lab/stage1-embedding-finetune.md](../docs/lab/stage1-embedding-finetune.md).

```bash
python -m venv .venv-train && . .venv-train/bin/activate
pip install torch --index-url https://download.pytorch.org/whl/rocm6.4   # or cu128 / cpu
pip install -r training/requirements.txt -r apps/nai-core/requirements.txt  # nai-core: same chunking as nAI

# 1. documents -> passages (nAI's own extractor and chunker; language detected per passage)
python training/embed/make_passages.py --input data/synthetic-corpus --output data/passages.jsonl \
    --license CC0-1.0 --source "synthetic NAS corpus v1" --author qwen2.5:7b

# 2. passages -> (query, passage) pairs with an approved open-weight teacher via Ollama
#    (add --resume to continue an interrupted run; --limit N takes a random sample)
python training/embed/generate_pairs.py --passages data/passages.jsonl --output data/pairs.jsonl \
    --model qwen2.5:7b

# 3. contamination check against nai-bench (exit 1 on overlap; with --write-clean it drops the
#    flagged rows, writes the rest and exits 0)
python training/embed/check_overlap.py data/pairs.jsonl

# 4. prepare everything and stop before training; then drop --dry-run to train
python training/embed/train.py --pairs data/pairs.jsonl --output-dir runs/embed-v1 --dry-run

# export any model to ONNX for fastembed and verify it gives the same vectors
python training/embed/train.py --export-only runs/embed-v1/model --output-dir runs/embed-v1/fastembed
```

### Scaled Vane 1 data (round 9)

Plan, sources, licenses and targets: [docs/lab/vane1-data-plan.md](../docs/lab/vane1-data-plan.md). Data stays in
git-ignored `training/data/vane1/`; manifests with checksums go to `training/manifests/`.

```bash
cd training/embed
# public texts (license per file, SHA-256, refuses CC-BY-SA/NC/ND and every nai-bench document)
python fetch_public.py --sources ../sources/vane1-data-v1.json --out ../data/vane1/public \
    --manifest ../manifests/vane1-data-v1-public.json
# chunk per source group; 5 % of whole documents (all language versions together) held out, eval-only
python make_passages.py --input ../data/vane1/public/eu --output ../data/vane1/passages-eu.jsonl \
    --holdout-output ../data/vane1/holdout-eu.jsonl --holdout-share 0.05 --license "…" --source "…" --author "…"
# varied synthetic documents (Ollama with infra/compose.bench.gen.yaml: 4 requests in parallel)
python generate_corpus.py --prompt-version corpus-v2 --per-language 700 --concurrency 4 --out ../data/vane1/synthetic
# queries, filter, overlap check, hard negatives (container), manifest
python generate_pairs.py --passages ../data/vane1/passages.jsonl --output ../data/vane1/pairs-raw.jsonl \
    --model mistral-small3.1 --prompt-version pairs-v2 --concurrency 4 --resume
python filter_pairs.py --input ../data/vane1/pairs-raw.jsonl --output ../data/vane1/pairs-filtered.jsonl
python check_overlap.py ../data/vane1/pairs-filtered.jsonl --write-clean ../data/vane1/pairs-clean.jsonl
python3 mine_negatives.py --input ../data/vane1/pairs-clean.jsonl --output ../data/vane1/pairs-mined.jsonl
python data_manifest.py --data ../data/vane1 --out ../manifests/vane1-data.json
# training (ROCm container): pairs whose positive is outside Granite's top 50 dropped, mined negatives where
# a pair has one, in-batch negatives for the rest
python3 train.py --pairs ../data/vane1/pairs-mined.jsonl --file-negatives --hard-negatives 1 \
    --max-positive-rank 49 --output-dir ../runs/vane-1-rc2 --release vane-1-rc2
```

### On an AMD GPU (ROCm) in Docker

PyTorch with ROCm runs in a container, the same way Ollama uses the GPU; nothing GPU-related is installed
on the host. The base image is `rocm/pytorch` (~12.5 GB compressed).

```bash
docker compose -f training/docker/compose.rocm.yaml build
docker compose -f training/docker/compose.rocm.yaml run --rm trainer python3 training/docker/gpu_check.py
docker compose -f training/docker/compose.rocm.yaml run --rm trainer \
    python3 training/embed/train.py --pairs training/data/pairs.jsonl --output-dir training/runs/vane-1-rc1 \
    --release vane-1-rc1
# the container runs as root: give the outputs back to your user afterwards
docker compose -f training/docker/compose.rocm.yaml run --rm trainer chown -R "$(id -u):$(id -g)" training/runs training/.cache
```

Smoke-tested on 2026-11-23 on an RX 7900 XTX (gfx1100): `gpu_check.py` (torch 2.15.0+rocm10.2.0, bf16 on),
then `train.py --max-steps 2` on 10 sample pairs: hard-negative mining, two training steps, save, ONNX export
and the fastembed check (min cosine 1.0000) in 37 s. Paths for the container are inside the repo
(`training/data`, `training/runs`, `training/.cache`), all git-ignored.

`data/` and `runs/` are not committed. Every passage records its `author` (required; hosted-API authors such
as Claude are refused) and each pair a `provenance` object (`author` = teacher and its license, prompt
version, `passage_author`, passage license and source, `use: training`). `train.py` refuses pairs without
it and writes `training_plan.json` (data hash, teachers, settings) next to the model. Both
`generate_pairs.py` and `train.py` read their inputs through `common.read_training_rows`, which refuses
files under `evals/nai-bench/` and any row that is marked `use: eval-only` (top level or `provenance`),
names a forbidden author (Claude, GPT, … in `author`, `passage_author`, `model` or `teacher`), or has
nai-bench item fields (`gold_answer`, `gold_facts`, `gold_sources`, `review_status`). Tests:
`pytest training/tests` (no PyTorch needed).

Verified on 2026-11-22 without a training run: passages and pairs on a 3-document sample (teacher
`qwen2.5:7b` via Ollama on ROCm), both refusal guards (nai-bench input, non-approved teacher), the overlap
check, `train.py --dry-run` (split, IR evaluator, mined negatives, trainer), and `--export-only` of the
base model (fastembed min cosine 1.0000 against PyTorch).
